# 循环样板提交器：按顺序重复下单

循环样板提交器负责按顺序提交样板任务，适合周期性请求一组产品。循环配平与种子管理由 [循环样板输入总成](cyclic_patterns.md) 负责；这里介绍提交器自己的任务控制。

## 从两个小订单开始

1. 将提交器接入有合成能力的 ME 网络，准备对应原料、样板和 CPU。
2. 放入两张容易区分结果的样板，并设置单次提交数量模式。
3. 选择合适的红石控制方式，开启提交。
4. 观察 GUI 光标、空闲／失败／已提交状态和 CPU 中的任务。
5. 用比较器读取当前样板序号，核对任务执行顺序。

先用少量原料验证一轮，再增加重复任务。输出持续回到网络后，才扩大产量。

## 失败后如何继续

“提交失败后重试”适合必须按完整顺序执行的任务；“跳过失败样板”适合各产品相互独立、允许先生产其他产品的场景。

缺少材料、CPU 忙碌或配方不可执行时，检查失败状态与网络中的合成计划，再决定使用哪种继续策略。

## 等待产物与提前取消

通常保留任务跟踪，等待产物完成。“样板发配后不等待产物直接取消任务”用于明确需要这种发配行为的特殊流程。启用前要确认材料进入哪里、产物如何保存，以及下一次提交何时允许发生。

右键电源操作会关闭并移动光标，同时放弃对当前合成任务的跟踪。调整光标前先在 CPU 界面核对已有订单。
